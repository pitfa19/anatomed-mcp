# Reproducible anatomy data repair

This pipeline repairs selectable identities without replacing good geometry. It adds the ninth `lymphoid` system and validates actual decoded vertex/index buffers using THREE.GLTFLoader and its Meshopt decoder.

## Inputs and preservation

- Original Z-Anatomy `Startup.blend` SHA-256: `9f08a17ea0115fed80b2a73ecdf0a1bc2ab2f6956f37c593ce23d513ea35afcd`.
- Source audit `inventory.json` and `mapping.json`, generated by `scripts/model-audit/source/` in the MCP repository. Their hashes are pinned in the generated provenance.
- The original eight GLBs, checked against the audit's SHA-256 values. They are never rewritten. This preserves the existing 0.5 mm vein/nerve treatment exactly, including the original converter's tessellation.
- `baseline-catalog.json` is the immutable 3,540-row pre-repair catalog, retaining all original display metadata for reproducibility and omission review.
- Blender 5.2.3 LTS was used for the new lymphoid export. No source `.blend` is saved. The original source checksum is verified before and after export.

## Run

Use absolute paths for all input/output arguments. Run from either repository with its existing Node dependencies installed. Replace the example paths with your local extracted source and audit locations.

```bash
blender --background --disable-autoexec --python scripts/anatomy-data/export-lymphoid.py -- \
  /absolute/source/Startup.blend /absolute/source-audit/inventory.json /absolute/assets/glb
node scripts/anatomy-data/generate.mjs /absolute/source-audit /absolute/assets/glb /absolute/assets
node --test scripts/anatomy-data/geometry.test.mjs
node scripts/anatomy-data/validate.mjs /absolute/assets /absolute/assets/glb
```

The exporter writes `lymphoid.glb` and `lymphoid-export.json`. The latter is a build input, not a runtime asset. Generation writes `parts-catalog.json`, `parts-neighbors.json`, and `anatomy-provenance.json`. The provenance includes the export report, all input/output hashes, every original catalog decision, every original source-object decision, and every converted-system node decision. The two repositories carry identical generation scripts and JSON outputs. Binary models remain local/ignored according to existing repository policy and are included by the separate release-packaging pipeline.

Repeat generation against the same inputs for byte-identical JSON outputs. There are no timestamps or absolute machine paths in those outputs. Blender binary reproducibility across versions is not promised.

## Selection and identity rules

1. Nerves and vessels use all positive finite renderable source-named mesh nodes in their existing GLBs. Preserve exact-match display metadata. Transfer metadata for a unique whitespace-only identity correction, but do not invent fuzzy aliases.
2. Other existing systems preserve their selected anatomical nodes, including named containers with valid mesh descendants. Only helper labels and targets with no positive finite surface are removed.
3. The source lymphoid collection has 163 eligible positive-surface objects. Spleen and the two thymus lobes already have valid targets in `organs`, so only the other 160 are exported.
4. Lymphoid evaluated vertices keep the source world matrix and use Blender's standard glTF Y-up conversion: `(x, y, z)` becomes `(x, z, -y)`. No rescale or recenter is applied. All 160 resulting bounds are checked against the enabled source inventory with a 0.01 mm tolerance.
5. Source-name/bounds candidates outside this approved repair are not automatically imported. Exact named mesh descendants establish structural coverage, not anatomical equivalence. Unresolved source identities remain explicit.

AABB means axis-aligned bounding box around transformed geometry. Neighbors use actual decoded world-space vertex AABBs, the 30 nearest box separations in metres, rounded to six decimals with stable catalog-order ties. These are spatial neighborhood candidates, not claims of anatomical contact or true surface distance. Legacy catalogs could include zero-face helper/profile boxes and stale identities, so the rebuilt neighbor lists intentionally differ.

## Acceptance results

| System | Selectable rows |
|---|---:|
| Skeleton | 271 |
| Muscles | 565 |
| Nerves | 582 |
| Vessels | 676 |
| Organs | 117 |
| Joints | 416 |
| Insertions | 728 |
| Regions | 256 |
| Lymphoid | 160 |
| **Total** | **3,771** |

- Every selectable row has a unique decoded target, finite world geometry and at least one positive-area triangle.
- All 1,258 nerve/vessel positive mesh nodes are selectable. The old exact-ID gap of 153 includes two whitespace-only corrections. The other 151 acquire new catalog rows.
- Original catalog decisions: 3,458 retained, 2 whitespace corrections, 64 stale identities omitted, 10 no-surface targets omitted, 6 helper labels omitted. These total all 3,540 original rows. All 160 lymphoid additions have original-source identity links.
- Source accounting: 3,247 helper/type exclusions, 14 no-surface exclusions, 2,818 exact-name or named-descendant inclusions, **1,105 unresolved historical source identities**. These total all 7,184 original objects. The unresolved count is not a missing-anatomy claim.
- All eight original GLB hashes match the audit. Maximum new lymphoid world-bound error is `2.9499844567126843e-8` metres.
- 113,130 neighbor edges are generated and recomputed during standalone validation. All references target valid catalog identities, with no self or duplicate edges.
- Six focused tests exercise named containers, world transforms, zero-area triangles, nonfinite data, helper/empty targets, and neighbor tie ordering. The full acceptance checker validates the real nine-system dataset, not fixtures.

The data-only checker does not establish visual quality or native-app behavior. Those checks belong to the renderer and coordinator acceptance workflows.
